# Export schema (versions 1 and 2)

The add-on writes version 2 from 0.3.0 on. Version 2 is version 1 plus the quest log observations
(`quest.accepted`, `quest.progress`, `quest.snapshot`) and `consent.quest_text`. Readers should keep
accepting version 1 files unchanged; in a version 1 file the quest log types are unknown and rejected.

- Machine-readable schemas: [`schema/chronicle-export.v1.schema.json`](../schema/chronicle-export.v1.schema.json)
  and [`schema/chronicle-export.v2.schema.json`](../schema/chronicle-export.v2.schema.json) (JSON Schema
  2020-12). They're generated by `tools/gen_schema.py`.
- The reference validator is the authority: [`reference/validator/ac_validate.py`](../reference/validator/ac_validate.py).
- Examples: [`tests/fixtures/valid_session.acx.txt`](../tests/fixtures/valid_session.acx.txt) (version 2) and
  [`tests/fixtures/valid_session_v1.acx.txt`](../tests/fixtures/valid_session_v1.acx.txt) (version 1). Both are
  synthetic.

## Envelope

```
ACX1:<length of JSON in bytes>:<CRC-32 of JSON, 8 lowercase hex>:<JSON>
```

A reader should do these steps in order:

1. Refuse anything over 1 MiB.
2. Decode it as UTF-8 and ignore a leading BOM and surrounding whitespace.
3. Check the prefix, the length and the CRC. If the length or CRC doesn't match, ask the person to copy the
   export again.
4. Parse it as JSON. Reject duplicate keys, `NaN` and `Infinity`, and nesting deeper than 12 levels.
5. Check every field. Unknown fields and unknown observation types are rejected.

The CRC-32 only catches copying mistakes. Exports are self-reported and anyone can edit them.

## Top level

| Field | Notes |
| --- | --- |
| `format` | Always `"adventure-chronicler.session"` |
| `schema_version` | `1` or `2` |
| `recorder` | `{ name: "AdventureChronicler", version }` |
| `game` | `{ id: "wow", flavor, client_version, build, interface, locale }` |
| `consent` | `{ character_identity, class_and_level, personal_loot }`, plus `quest_text` in version 2: the export settings at export time. A `quest.accepted` `description` is only allowed when `quest_text` is true |
| `character` | `name` and `realm` only if `character_identity` is true; `class` and `level` only if `class_and_level` is true |
| `session` | `{ id, title, state, interrupted, started_at, ended_at, clock: "unix_seconds", segments[] }` |
| `observations[]` | `{ seq, t, type, certainty, data, repeats, clock_note }` |
| `author.notes[]` | `{ id, t, kind: "note"\|"bookmark", text, edited_at }`. This is the player's own writing. |
| `integrity` | `{ observations_dropped, dropped_by_type, merged_repeats, deleted_by_user, self_reported: true }` |

The session `id` is random, like `s-<8 hex>-<12 hex>`. It doesn't identify the player.

## Observation types

| Type | Certainty | Data |
| --- | --- | --- |
| `zone.enter` | confirmed | `map_id`, `map`, `zone` |
| `instance.enter` / `instance.leave` | confirmed | `instance { id, name, type, difficulty_id, difficulty, max_players }` |
| `encounter.start` | confirmed or uncertain | `encounter_id`, `name`, `difficulty_id`, `group_size`, `restricted_values` |
| `encounter.end` | confirmed or uncertain | Same as start, plus `result` (`success`, `wipe_or_reset` or `unknown`) and `duration` |
| `quest.accepted` (v2) | confirmed | `quest_id`, `title`, `level`, `objectives[]`, `summary` (the short objective text, up to 1,000 characters), `description` (the quest giver's full text, up to 4,000 characters, only with `consent.quest_text`), `text_cut` (true when either text was shortened) |
| `quest.progress` (v2) | confirmed | `quest_id`, `title`, `index`, `text`, `fulfilled`, `required`, `finished`, `updates` (changes merged into this entry), `last_t` (time of the last merged change). The entry's `t` is the first change |
| `quest.snapshot` (v2) | seen | `quests[]` (each `quest_id`, `title`, `level`, `complete`, `objectives[]`), `listed` (quests in the log), `kept` (up to 40) |
| `quest.rewards_offered` | seen | `quest_id`, `title`, `choices[]`, `guaranteed[]` (each item has `index`, `item_id`, `name`, `count` and `name_pending`) |
| `quest.reward_selected` | inferred or uncertain | `quest_id`, `choice_index`, `item_id`, `name` |
| `quest.turned_in` | confirmed | `quest_id`, `title`, `xp`, `money_copper` |
| `item.received` | inferred | `quest_id`, `item_id`, `name`, `count_delta`, `basis` |
| `loot.seen` | seen | `items[]` (opt-in) |
| `pvp.battleground_enter` / `_leave` | confirmed | `instance_id`, `name`, and `result_recorded` on leave |
| `pvp.battleground_result` | confirmed or uncertain | `instance_id`, `name`, `winner`, `player_faction`, `outcome` (`won`, `lost` or `unknown`) |
| `player.death` | confirmed | `context`, `zone` |
| `marker.bookmark` | confirmed | `note_id` |
| `marker.screenshot` | confirmed or uncertain | `preset`, `status` (`succeeded`, `failed` or `unconfirmed`) |

An objective is `{ index, text, type, fulfilled, required, finished }`, for example
`{ index: 1, text: "Fixture Wolf slain: 3/8", fulfilled: 3, required: 8, finished: false }`. Up to 16 per quest.
Objective progress is what the quest log showed. It doesn't say who did the work, and a snapshot quest marked
`complete` only means the log said so when recording started.

Every data field is optional, because the game doesn't always provide it. A missing value stays missing and
is never guessed.

## Duplicate imports

The fingerprint is the session `id` plus the SHA-256 of the JSON body. An importer should:

- treat the same id and the same hash as a **duplicate**: do nothing and point to the existing draft;
- treat the same id with a different hash as a **revision**: offer to update the existing private draft, and
  never create a second one;
- keep at most one draft per session id per account.

Importing never awards anything. On QuestersBoard, XP comes only from publishing, which goes through its
normal review.

## Mapping to a QuestersBoard Chronicle draft

The scaffold (`reference/scaffold/ac_scaffold.py`) does this mapping. It's deterministic and doesn't use AI.

| QuestersBoard field | Filled with |
| --- | --- |
| `title` (3 to 140 characters) | The session name, or `Adventure on <date>` |
| `attempted` ("The plan") | A placeholder for the author |
| `happened` ("What happened") | A timeline of what was recorded, with certainty labels and any gaps marked as unknown |
| `outcome` | Always `unknown`; the author chooses |
| `moments` ("Best moments") | Bookmarks and successful screenshot markers, or a placeholder |
| `body` ("The story") | A placeholder, followed by the author's own notes word for word |
| Activity type | Suggested only (`battleground`, `raid`, `dungeon`, `quest` or `custom`); the author picks |
| State | `draft` (private). It's never `pending_review` or `published` on import. |

Each long field is kept to 8,000 characters. If a field would be longer, it keeps whole lines and ends with
`[...and N more events not shown here; they are still in the export.]`. It never cuts text off silently.

The import must **never** call QuestersBoard's AI suggestion feature, unless the author asks for it
separately and gives explicit consent.

## A simple import form

This is a proposal for QuestersBoard. QuestersBoard isn't changed by this repository.

One screen and three steps:

1. **Paste.** A single large text box labelled "Paste your Adventure Chronicler export", with a **Check**
   button. Nothing else shows until the check passes. An error is one plain sentence, such as "This export
   was damaged while copying. Copy it again."
2. **Preview.** The draft fields are shown already filled in and editable. There's one required choice
   (character) and one with a suggested default (activity type). Outcome is set to "Unknown". There's no
   other required field.
3. **Save as private draft.** It saves and opens the draft in the normal Chronicle editor. A one-line note
   says: "Only you can see this. Publishing works the same as any other Chronicle entry."

Advanced details (session id, client version, counts of dropped or merged events) go behind a collapsed
"Details" link. The form never shows raw JSON unless asked.
